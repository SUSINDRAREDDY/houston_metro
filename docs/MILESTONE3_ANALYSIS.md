# Milestone 3 - Written Analysis

Our final MetroAI v1 image reports **297,289,101 bytes (297.3 MB)** in local Docker. Artifact Registry reports **69,889,276 bytes (69.9 MB)** for the compressed AMD64 image. These are different storage measurements of the same published artifact. We reduced the runtime image with a multi-stage Dockerfile: Node builds the frontend in a separate stage, and the final Python slim image receives only the exported static frontend. Node, npm, and frontend build dependencies are therefore absent from the runtime image. We also use `pip install --no-cache-dir` to avoid retaining package-download caches.

Our `.dockerignore` excludes `.env` and `.env.*` to keep credentials out of the build context; `.git` to exclude repository history; `.venv` to avoid copying machine-specific Python packages; and `data` to exclude the large transit database, which belongs in a persistent volume. It also excludes `frontend/node_modules`, `frontend/.next`, and `frontend/out` because the frontend is rebuilt inside Docker, and `__pycache__` because Python bytecode can be regenerated. These exclusions reduce unnecessary context and keep laptop artifacts out of the deployment.

We supply our API keys at runtime through environment variables. We exported v1 and checked its configuration, build history, and all ten decompressed image layers against our three current runtime credentials. We found zero credential matches, zero `.env` files, and no application credential variables embedded in the image configuration. The verification script is included in our repository. This verifies the credentials checked, rather than claiming an unrestricted security audit.

For cost control, we reuse our existing e2-small VM and maintain a **$50 monthly project budget** with email alerts at **10%, 20%, 25%, 50%, and 100%**, covering both threshold lists in the assignment. The October 8 budget view showed **$0.00 net spending**, including **$3.07 in savings**; zero net spending does not mean zero resource usage. Our budget covers the MetroAI project, and we review current spending. Alerts notify us; they do not automatically stop the VM.
